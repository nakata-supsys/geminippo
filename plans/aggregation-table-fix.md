# 工数集計機能の表示崩れ修正計画

## 問題の概要

工数集計機能で生成されるテーブルの形式が崩れており、以下の症状が発生しています：

1. **日付列が空白**になっている
2. **種別列と工数列が結合**されて表示されている
3. テーブルの構造が期待通りでない

### 実際の表示例（問題あり）

```
| 日付 | 種別 | 工数 | 内容 |
|---|---|---|---|
| **▼ 02/12(木)** | 合計: 11.0時間** |  |  |
|  | [CS_ウィゴー] | 4.0時間 | 定例MTG・実装・審査、AIMSTAR PS定例MTG、データ対応 |
```

### 期待される表示

```
▼ 2023/10/26(木) | 合計 8.0 時間

| 種別 | 工数(時間) | 内容 |
|---|---|---|
| PROJ-001: A社様導入支援 | 4.5 | 定例MTG、課題管理表の更新、設計書の作成 |
```

## 根本原因の分析

### 1. AIプロンプトの問題

[`Services.js:191-220`](Services.js:191-220)で定義されているプロンプトは正しい形式を指定していますが、AIが以下の点で指示を守っていません：

- **見出しとテーブルの間の空行**が挿入されていない
- **テーブルに4列（日付、種別、工数、内容）**を含めてしまっている（指示では3列のみ）
- **日付情報が見出しとテーブルの両方**に含まれている

### 2. フロントエンドのパース処理の問題

[`js.html:648-721`](js.html:648-721)の`renderAggResult`関数では：

- Markdownのパース処理が`marked.parse()`に完全依存している
- AIが生成した不正な形式のテーブルをそのまま表示してしまう
- テーブル構造の検証やフォールバック処理がない

### 3. プロンプトの引数渡しの問題

[`Services.js:221`](Services.js:221)で`generateAggregationWithGemini`を呼び出す際、`newAggregationPrompt`を渡していますが、[`AI.js:577-611`](AI.js:577-611)の関数定義では**7番目の引数として`instruction`を受け取り、8番目の引数がない**ため、カスタムプロンプトが無視されています。

## 修正方針

### 修正1: AI.jsの関数シグネチャを修正

`generateAggregationWithGemini`関数に`customPrompt`引数を追加し、カスタムプロンプトを正しく受け取れるようにします。

```javascript
function generateAggregationWithGemini(logText, modelType, start, end, projectList, avgWorkHours, instruction, customPrompt) {
  const prompts = getPromptSettings();
  let p = customPrompt || prompts.aggregation; // カスタムプロンプトを優先
  // ... 以下既存処理
}
```

### 修正2: プロンプトの改善

より明確で厳格な指示を追加します：

```markdown
### 【重要】出力形式の厳守事項
1. 各日付の見出しの直後に、**必ず空行を1行**入れてください
2. テーブルは**必ず3列（種別、工数(時間)、内容）のみ**としてください
3. 「日付」列は絶対に含めないでください
4. 見出し形式: `▼ yyyy/MM/dd(E) | 合計 XX.X 時間`
5. テーブルのヘッダー行: `| 種別 | 工数(時間) | 内容 |`
6. 区切り行: `|---|---|---|`

### 悪い例（絶対にこうしないこと）
| 日付 | 種別 | 工数 | 内容 |
|---|---|---|---|
| 02/12 | プロジェクトA | 4.0時間 | 作業内容 |

### 良い例（必ずこの形式で出力すること）
▼ 2023/10/26(木) | 合計 8.0 時間

| 種別 | 工数(時間) | 内容 |
|---|---|---|
| PROJ-001: A社様導入支援 | 4.5 | 定例MTG、課題管理表の更新 |
```

### 修正3: フロントエンドでの検証とフォールバック

`renderAggResult`関数に以下の処理を追加：

1. **テーブル構造の検証**
   - 列数が3列であることを確認
   - 4列以上の場合は自動的に最初の列（日付列）を削除

2. **空のテーブル行の削除**
   - 既存の`emptyTableRegex`処理を強化
   - データが空の行を検出して削除

3. **見出しとテーブルの間の空行を強制挿入**
   - 正規表現で見出し直後にテーブルが来ている場合、空行を挿入

```javascript
// テーブル構造の修正処理
function fixTableStructure(text) {
  // 1. 見出しとテーブルの間に空行を挿入
  text = text.replace(/(▼[^\n]+)\n(\|[^\n]+\|)/g, '$1\n\n$2');
  
  // 2. 4列テーブルを3列に修正（最初の列を削除）
  const lines = text.split('\n');
  const fixedLines = lines.map(line => {
    // テーブル行を検出（4つ以上のパイプを含む）
    if (line.match(/^\|[^|]+\|[^|]+\|[^|]+\|[^|]+\|/)) {
      // 最初の列を削除
      return line.replace(/^\|[^|]+\|/, '|');
    }
    return line;
  });
  
  return fixedLines.join('\n');
}
```

### 修正4: エラーハンドリングの強化

AIが期待通りの形式を出力しなかった場合のフォールバック処理：

```javascript
// テーブルが全く生成されていない場合
if (!dailyText.includes('|---|')) {
  dailyText = "⚠️ テーブル形式での表示に失敗しました。\n\n" + dailyText;
}
```

## 実装の優先順位

1. **最優先**: AI.jsの関数シグネチャ修正（これがないとカスタムプロンプトが無視される）
2. **高**: プロンプトの改善（AIの出力品質を向上）
3. **中**: フロントエンドの検証・修正処理（AIが失敗した場合のフォールバック）
4. **低**: エラーメッセージの改善（ユーザー体験の向上）

## 期待される効果

- ✅ テーブルが正しく3列で表示される
- ✅ 日付列が見出しのみに表示され、テーブル内には含まれない
- ✅ 見出しとテーブルの間に適切な空行が入る
- ✅ AIが失敗した場合でも、フロントエンドで自動修正される
- ✅ ユーザーが期待通りの見やすい表形式で工数を確認できる

## 注意事項

- Markdownのテーブル記法は`marked.js`ライブラリに依存しているため、ライブラリの仕様に合わせた形式で出力する必要がある
- AIの出力は完全には制御できないため、フロントエンド側での検証・修正処理が重要
- ユーザーが「AIに修正を指示」機能を使った場合でも、同じ検証・修正処理が適用される
