# UI文言ガイド（表示・保存・送信 統一）

## 基本方針
- ボタンは「動詞 + 対象」を短く書く。
- 見出しは役割で分ける。
  - 設定系: `◯◯設定`
  - 一覧系: `◯◯一覧`
- 同じ意味の操作に別語を使わない（例: 保存/反映/適用の混在を避ける）。

## ボタン文言ルール
1. `表示`
- 画面内に結果を出す操作
- 例: `今日のTODOを表示`

2. `保存`
- 設定値を保持する操作
- 例: `設定を保存する`, `通知設定を保存`

3. `送信`
- 外部へ投稿する操作
- 例: `このTODOをSlackに送信`

4. `開始`
- 実行ジョブを開始する操作
- 例: `集計を開始`

## 見出し文言ルール
- 推奨:
  - `日報設定`
  - `TODO設定`
  - `プロジェクト名寄せ設定`
  - `除外ルール一覧（Slack未返信）`
- 非推奨:
  - 同一階層で `詳細` の多用
  - 意味が重複する接頭辞（例: `設定設定`）

## ツールチップ/説明文ルール
- 1文目で機能の目的
- 2文目で注意点（制約・省略条件）
- 3文目で利用者アクション（必要時）

## 現行UIの運用メモ
- `設定を保存する` は接続/日報設定で共通利用中（維持）
- TODOは `表示` と `送信` を明確に分離済み（維持）
- 新規追加ボタンは上記4分類のどれかに必ず寄せる
